# Спецификации проекта

OpenSpec описывает действующие возможности маркетплейса и изменения к ним.
Основные спецификации находятся в `specs/<capability>/spec.md`, текущие изменения —
в `changes/<change>/`, архив завершённых изменений — в `changes/archive/`.

## Работа над следующим изменением

1. Прочитай [контекст и правила](config.yaml), [CLAUDE.md](../CLAUDE.md)
   и [AGENTS.md](../AGENTS.md).
2. Посмотри текущие возможности через `openspec list --specs` и прочитай
   относящиеся к задаче `spec.md` целиком, включая сценарии.
3. Вызови `/opsx:propose <имя-изменения>` с описанием результата. Предложение
   создаёт `proposal.md`, изменения требований в `specs/` и проверяемые задачи
   в `tasks.md` внутри каталога изменения. Технические решения записываются
   в `design.md`, когда это требуется по условиям схемы.
   Если меняется только документация или внутреннее устройство без изменения
   поведения, укажи это сразу: после создания change и до генерации delta specs
   агент должен установить `skip_specs: true` в
   `openspec/changes/<имя-изменения>/.openspec.yaml`. При этом файлы delta specs
   не создаются; флаг несовместим с их наличием.
4. Проверь границы и решения до реализации. Для действующей возможности
   используй её точный путь в `Modified Capabilities`. Требование под
   `MODIFIED Requirements` должно содержать все сохраняемые сценарии.
5. Выполни `/opsx:apply <имя-изменения>`. Запускай проверки, предусмотренные
   задачами; фиксируй реальные результаты.
6. Проверь изменение командой
   `openspec validate <имя-изменения> --type change --strict --no-interactive`.
   Проверка формата не заменяет тесты кода и оценку поведения модели.
7. После завершения задач вызови `/opsx:archive <имя-изменения>`.
   Проверь синхронизацию изменений требований с основными спецификациями.
   Если нужно обновить основные спецификации раньше, используй
   `/opsx:sync <имя-изменения>`; само изменение при этом остаётся открытым.

## Проверка описания

- `openspec list --specs` — перечень описанных возможностей.
- `openspec validate --specs --strict --no-interactive` — формат всех основных спецификаций.
- `openspec doctor --json` — состояние корня OpenSpec и связей с другими корнями.
- `openspec list --json` — открытые изменения и выбранный корень проекта.

Коммит, отправка ветки, публикация PR, платная оценка поведения модели и релиз
требуют отдельного разрешения. Перед выпуском выполняется весь порядок из
[docs/release.md](../docs/release.md).
