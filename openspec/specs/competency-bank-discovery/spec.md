# Обнаружение банков компетенций

## Purpose

Подключать готовые своды нескольких банков без перезаписи чужих записей, показывать найденные компетенции и предлагать точки входа, сохраняя различие между обнаружением, публикацией и допуском к применению.

## Requirements

### Requirement: Независимая публикация банков

Публикатор банка SHALL на `SessionStart` подключать своды текущей установки отдельными ссылками в `~/.claude/dpf.d/`, сохраняя различимое владение ссылкой после исчезновения прежней версии плагина. Он MUST обновлять собственные записи и удалять собственные ссылки на больше не поставляемые своды при непустой поставке, не переписывая человеческий `.dpf.paths` и прежний `frameworks.published`. Публикация MUST NOT означать положительный допуск пакета.

#### Scenario: Обновление установленной версии
- **WHEN** банк снова публикует непустую поставку из новой версии плагина
- **THEN** его ссылки переходят на текущие своды, а чужие банковские записи и человеческий список корней сохраняются.

#### Scenario: Старый плагин удалён
- **WHEN** прежняя цель собственной ссылки исчезла, но тот же банк запускает публикатор из текущей установки
- **THEN** владение определяется без разыменования пропавшей цели, и собственная ссылка может обновиться.

### Requirement: Коллизия не захватывает чужую запись

Публикатор SHALL при совпадении ID с записью, не принадлежащей этому банку, сохранять чужую запись и сообщать причину. Отсутствие `CLAUDE_PLUGIN_ROOT`, пустая поставка или перехваченная ошибка файловой операции MUST давать диагностику в stderr без блокировки старта сессии: код хука `0` не удостоверяет успех публикации.

#### Scenario: Два банка используют один ID
- **WHEN** второй банк публикует ID, уже занятый чужой записью
- **THEN** чужая запись не заменяется, а диагностика называет коллизию; хук возвращает `0`.

#### Scenario: Публикация недоступна
- **WHEN** создание ссылки завершается ошибкой файловой системы
- **THEN** хук сообщает ошибку и возвращает `0`; вызывающий не должен читать этот код как доказательство подключения банка.

### Requirement: Карта найденных пакетов

Стартовая карточка SHALL использовать JSON-список резолвера, исключать затенённые строки, группировать найденные пакеты по уровням и помечать просроченные. При усечении она MUST указывать число оставшихся и путь к полному списку. Карточка показывает обнаружение, а не только допущенные пакеты; она MUST NOT служить разрешением на применение.

#### Scenario: Пакетов нет
- **WHEN** резолвер не вернул пакеты либо вызов списка не удался
- **THEN** карточка не печатает пустое объявление и не блокирует сессию.

#### Scenario: Найден просроченный пакет
- **WHEN** незатенённый пакет присутствует в списке с `stale: true`
- **THEN** карточка может показать его с пометкой просрочки, не обещая допуска.

### Requirement: Подсказки по ID и ключевым словам

Хук запроса SHALL сопоставлять точные ID с ID допущенных строк списка резолвера и отдельно искать ключевые слова `cues` в картах без смыслового модельного поиска. Подсказка MUST оставаться предложением перейти к `dpf-apply`, не выполнять применение и не заменять его допуск. Текущий канал точных ID учитывает и затенённые допущенные копии, а канал `cues` не фильтрует совпадения по допуску. Вывод обоих каналов MUST NOT трактоваться как подтверждение допуска выбранной резолвером копии.

#### Scenario: Ни одна копия ID не допущена
- **WHEN** запрос содержит только точный ID без допущенных строк в списке резолвера и не совпадает с ключевыми словами карт
- **THEN** канал точных ID не предлагает этот пакет.

#### Scenario: Допущенная копия затенена
- **WHEN** точный ID имеет запрещённую проектную копию и допущенную затенённую банковскую копию, а запрос не совпадает с ключевыми словами карт
- **THEN** канал точных ID может предложить этот ID, но обычный поиск выбирает запрещённую проектную копию и отказывает; подсказка не доказывает допуск.

#### Scenario: Совпадение ключевого слова
- **WHEN** запрос совпадает с `cues` карты
- **THEN** хук может предложить ID с указанием обязательного `declaredUse`; фактический допуск проверяется при обращении к методу применения.

### Requirement: Ограниченный и необязательный вывод подсказки

Хук SHALL устранять повторные ID в одном выводе, показывать не более трёх подсказок и направлять к полному списку при большем числе совпадений. При доступном сессионном хранилище уже показанный ID MUST исключаться из следующих подсказок этой сессии; ошибка хранилища может вернуть повторную подсказку и не должна блокировать запрос.

#### Scenario: Много совпадений
- **WHEN** найдены более трёх ещё не показанных ID
- **THEN** хук показывает первые три и указатель на остаток, записывая в сессионное хранилище только показанные ID.

#### Scenario: Нет совпадений
- **WHEN** запрос не содержит известных ID и ключевых слов карт
- **THEN** хук не печатает подсказку и возвращает `0`.

### Requirement: Приём пакета и локальная граница

Правила банка SHALL требовать двух слоёв приёма: машинного `--verify --scope bank` и содержательной оценки критика, согласующей `kind`, источники и объявленный контекст. Пакеты `seedOnly` и `repairBeforeDPFUse` MUST NOT приниматься по одной корректной структуре. Правила опубликованного LPF MUST требовать адаптации и новой оценки для чужого контекста; вердикт допуска исходного пакета не переносится на новое применение автоматически. Содержательный слой является договором работы модели и участника банка, а не проверкой публикационного хука.

#### Scenario: Аккуратная заготовка
- **WHEN** пакет имеет корректные поля, но критик установил `seedOnly`
- **THEN** договор банка не разрешает принять пакет как пригодный свод.

#### Scenario: LPF нужен в другом проекте
- **WHEN** локальный свод для конкретного конвейера хотят использовать в чужом контексте
- **THEN** договор требует адаптировать контекст и читателя и провести свежую оценку под новым `declaredUse`.
