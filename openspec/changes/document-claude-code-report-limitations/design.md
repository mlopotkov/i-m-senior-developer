# Design

## Context

В корневом README описан состав маркетплейса, а в `plugins/planner/README.md` — устройство planner. Действующая команда уже останавливается, если обязательный файл отчёта пуст. Причина возможного отказа на стороне Claude Code приведена в [issue #101519](https://github.com/anthropics/claude-code/issues/101519).

## Goals / Non-Goals

**Goals:** назвать ограничение рядом с описанием planner и связать оба README с одним проверяемым источником.

**Non-Goals:** менять команду, формат отчёта, настройку среды или поведение хоста.

## Decisions

- В корневом README дать короткое предупреждение и ссылку на issue; в README planner объяснить различие между отказом роли до `Write` и отказом инструмента по имени файла. Не копировать содержимое баг-репорта целиком.
- Наблюдение пользователя о `CLAUDE_CODE_REMOVE_PROMPT_STRINGS` описывать без гарантии: переменная недокументирована, применяется к новому процессу и не отменяет отдельную проверку имён. Не устанавливать её автоматически в проекте.
- В delta-spec добавить только договор документации известного ограничения. Гейты `/plan-do` и машинные форматы не изменять.

## Risks / Trade-offs

- **Ограничение хоста может измениться** — ссылаться на открытый issue и не привязывать инструкцию к одной версии CLI.
- **Документацию примут за исправление** — прямо сообщать, что пустой файл не означает выполненную фазу и что на поведение субагента эта правка не влияет.
