# Proposal

## Why

Claude Code может добавить субагенту инструкцию не записывать Markdown-отчёты, хотя `/planner:plan-do` выдал ему точный путь. В наблюдённом случае роль не вызвала `Write`, файл остался пустым и цикл остановился. Это ограничение хоста нужно назвать пользователям без обещания, что изменение роли или имени файла устранит его.

## What Changes

- Добавить раздел **Known limitations** в корневой `README.md` и `plugins/planner/README.md`: описать возможный отказ субагента писать обязательный отчёт и сослаться на [баг Claude Code](https://github.com/anthropics/claude-code/issues/101519).
- Отделить отказ модели до вызова `Write` от отдельной проверки имён файлов инструментом `Write`. Сообщить, что пользователь наблюдал успешный запуск нового процесса после удаления системного примечания через недокументированную `CLAUDE_CODE_REMOVE_PROMPT_STRINGS`, но не выдавать это за поддерживаемое исправление плагина или гарантию для каждого окружения.
- Добавить в существующую спецификацию выполнения плана требование документировать это внешнее ограничение; работа команды и форматы отчётов не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `plan-execution`: зафиксировать обязанность описывать ограничение Claude Code на файловые отчёты субагентов с первичным источником и границей подтверждения.

## Impact

Изменяются только `README.md`, `plugins/planner/README.md` и delta-spec `plan-execution`. Исходники команд и ролей, `SubagentHandback`, разрешения хоста, имена файлов и платные проверки остаются вне объёма. Пустой отчёт не превращается в успешную фазу от одной документационной правки.
