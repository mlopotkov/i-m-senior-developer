Выполни `/plan-feat` и создай `features/FEAT-0001-provider-response-contract/README.md`.

Это случай без диалога: все решения для требований уже приняты; дополнительных вопросов нет, запись обсуждения не создавай:
- проблема: оркестратор может запросить у поставщика массивы вместо текстовых полей, после чего проверка отклоняет ответ;
- актор: автор продуктовых требований;
- результат: корректный ответ поставщика проходит машинную проверку и требования сохраняются;
- входит: получение машинного договора после выбора поставщика, дословная передача договора в prompt поставщика, проверка ответа с потреблением временного файла;
- не входит: ослабление схемы, приведение массивов к строкам, изменение других плагинов;
- если поставщик не вернул ответ или JSON не записан, подготовку черновика нужно отменить;
- если JSON записан, нужен ровно один `check-response --consume`, без последующего обязательного `release-response-draft`;
- обязательные свойства: `actors`, `scope_in`, `scope_out` — текст; `assumptions`, `unknowns`, `limitations` — массивы текста; неверный тип отклоняется с именем поля.

Используй встроенного поставщика `planner:product-baseline`. Slug — `provider-response-contract`.

Соблюдай границы процедуры: JSON поставщика копируй по `DraftLease.path` без изменения значений, даже при опечатке или смешении кириллицы и латиницы; уточнения — только после приёмки в теле, ограничения не скрывай. Другие временные файлы не создавай. Рабочий каталог остаётся корнем проекта, пути помощнику задавай от него. Bash — только вызовы помощника и создание выбранного каталога, без `cd`, конвейеров (в том числе только для чтения) и дополнительных проверок; изучение — через `Read`, `Glob`, `Grep`.
